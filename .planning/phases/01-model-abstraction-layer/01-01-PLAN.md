**Step 1: Implement `GeminiNanoModelService`.**

Create `libs/shared/model/src/lib/gemini-nano-model.service.ts`. This is an internal class (not exported from barrel). Key implementation details:

- Extends `ModelService`
- `modelName` signal: `signal('Gemini Nano')`
- `status` signal: starts at `'checking'`
- `isReady` computed: `computed(() => this.status() === 'ready')`
- `contextWindowSize` signal: `signal(0)` (populated on anchor creation)
- `contextUsage` signal: `signal(0)` (updated on anchor creation and per-pass sessions)
- Private `#anchorSession` field (never exposed, never destroyed)
- `initialize()`: async method called by environment initializer. Flow:
  1. Set status to `'checking'`
  2. Call `LanguageModel.availability()` -- if not `'available'`, set status accordingly and return early (for `'downloadable'`/`'downloading'`/`'unavailable'`)
  3. Set status to `'initializing'`
  4. `LanguageModel.create()` with NO `initialPrompts` (empty system prompt -- zero token cost per CONTEXT.md)
  5. Store as `#anchorSession`
  6. Read `session.contextWindow` into `contextWindowSize` signal
  7. Read `session.contextUsage` into `contextUsage` signal
  8. Set status to `'ready'`
  9. Wrap in try/catch: on failure, set status to `'unavailable'` (no retry per CONTEXT.md)
- `checkAvailability()`: calls `LanguageModel.availability()`, maps result
- `downloadModel(onProgress?)`: calls `LanguageModel.create({ monitor })` with download progress events. After download completes, do NOT destroy the download session -- assign it as the anchor session and transition to `'ready'`
- `createSession(preset)`: creates a new session with `LanguageModel.create({ initialPrompts: [{ role: 'system', content: geminiNanoPrompts[preset] }] })`. Returns a `ModelSession` object where:
  - `prompt()` delegates to `session.prompt()`
  - `promptStreaming()` delegates to `session.promptStreaming()`
  - After session creation, update `contextUsage` signal from the new session
  - `destroy()` calls `session.destroy()` on the pass session (NOT anchor), then re-reads `#anchorSession.contextUsage` back into the signal

Important: Use `provideEnvironmentInitializer()` (not the deprecated `ENVIRONMENT_INITIALIZER`) per research findings. The CONTEXT.md says "ENVIRONMENT_INITIALIZER" but the user's intent is "eager non-blocking initialization inside provideModel()" -- `provideEnvironmentInitializer()` is the Angular 21 replacement.

Important: Avoid naming any variable `window` -- it shadows the global (per CONTEXT.md).

**Step 4: Implement `provideModel()` factory.**

Create `libs/shared/model/src/lib/model.providers.ts`:

```typescript
import { EnvironmentProviders, inject, makeEnvironmentProviders, provideEnvironmentInitializer } from '@angular/core';
import { ModelService } from './model.service';
import { GeminiNanoModelService } from './gemini-nano-model.service';
import { Phi4MiniModelService } from './phi4-mini-model.service';
import { UnsupportedModelService } from './unsupported-model.service';

export function provideModel(): EnvironmentProviders {
  const impl = resolveModelServiceImpl();

  return makeEnvironmentProviders([
    { provide: ModelService, useClass: impl },
    provideEnvironmentInitializer(() => {
      inject(ModelService).initialize();
    }),
  ]);
}
```

Browser detection in `resolveModelServiceImpl()`:

1. `typeof LanguageModel === 'undefined'` --> `UnsupportedModelService`
2. `navigator.userAgent.includes('Edg/')` --> `Phi4MiniModelService` (note: `Edg/` not `Edge/` to avoid legacy EdgeHTML confusion)
3. Default --> `GeminiNanoModelService` (covers Chrome, Opera, unknown Chromium with API)

Do NOT install Angular CDK for browser detection -- userAgent parsing is the correct approach per research (CDK `Platform.BLINK` is true for both Chrome and Edge).
